## 1. The repository could not build or test itself, and that hid everything

Three defects, all from the 2026-08-20…28 memory-reduction window. None had ever been
seen, because the first blocked `bin/build` before the other two could be reached.
Full write-up: `docs/status/evidence/toolchain-repair-2026-09-02.md`.

| | before | after |
|---|---:|---:|
| `analyze src --only undefined.,parse.error` | 73 errors | **0** |
| `bin/build` | refuses (bootstrap gap) | **77 s** |
| `lib/manticore_stdlib.o.sig` | **0 functions** (155 B) | **2788** (269 KB) |
| AOT suite | 495 / 1028 | **1026 / 1028, 0 failed** |

1. **`Dns.php`** was the only namespaced file in `src/Runtime/Stdlib/`. The namespace is
   deliberate (Zend owns `dns_get_record`), but its 26 private `__mc_dns_*` wire helpers
   sat inside it while every call site — and `Net.php`, which is global — spelled the
   GLOBAL name. They resolved for nobody. Split into a global `DnsWire.php`.
2. **Every library `.sig` was empty.** Emission drains `$module->functions`, and
   `Sig::emitModule` builds the interface by walking exactly that table, *after*
   emission. A stdlib `.o` full of symbols behind an interface declaring none.
   **531 of 1028 AOT cases were red on this one bug.**
   ⚠ The guard must be `$this->emitLibrary`, **not** `$module->isLibraryModule` — the
   latter is `emitLibrary && exportTypes` (`Main.php:3852`) and is false for the stdlib,
   so the obvious spelling changes nothing and reads as "the drain was innocent".
3. **Lazy helper bodies were dropped.** Both drain loops were `foreach`, which iterates
   a COPY, so a helper registered *during* the drain was never written. The buffered
   (`MANTICORE_STREAM_IR=0`) path had lost its drain entirely. Both now share
   `drainLazyHelpers()`, run to a fixpoint. ⚠ The registries double as the generator's
   dedup table — a key may not be removed before its body is written; the body string is
   blanked and the key kept as a tombstone.

`bin/build` now fails loudly if the stdlib interface comes out empty.

### The leaking shape, isolated with paired controls

```
$h->t = [new Tok, new Tok];                   60000 alloc / 60000 reclaim   ✓
$tmp=[]; $tmp[]=new Tok;      (no prop store) 40000 / 40000                 ✓
$tmp=[]; $tmp[]=new Tok; $h->t=$tmp;          60000 / 20000                 ✗
```

Both conditions are required. The BUFFER is always reclaimed (`array_reclaim=20000`);
only elements leak. `__mir_array_retain_obj` co-owns every element on each call, while
release gives elements back only once, at rc→0. Two retains, one returned reference,
every element parked at rc 1 forever. This is verbatim the open gap recorded in
`element-drop-epic-2026-08-10`.

That is `Parser::__construct` — `$filtered = []; $filtered[] = $tok; $this->tokens =
$filtered;` — i.e. the 9.2M tokens.

Live as `prop_from_literal` / `prop_from_local` in `tools/prof/rcbalance.php`.

## 4. Exactly where this stands, and the next step

Three links; two are closed.

**Closed — the local's release type.** First-write-wins froze it at `vec[unknown]` from
`$a = []`, which is usually the ONLY `store_local` to the name (appends are
`store_element`). The emitter called `__mir_array_release` where
`__mir_array_release_obj` was needed. Refining from the LOADS fixes it:
`array_release_obj` 40000 → 60000 on the probe.

**Closed — the local is now accepted as own-element.** `arrayRetainFlavor` ignored the
refined type because its "uninformative" test was `element === null`, and `vec[unknown]`
has a real `Type` there. Treating an UNKNOWN element as uninformative makes the fallback
win. `MANTICORE_OWNEL_TRACE=1` now prints `OWNEL? $tmp YES vecobj`.

**Closed — the class `drop_fn` side** (`685764f`, `MANTICORE_RC_PROP_DROP=1`, default OFF).
The arithmetic was as stated: elements sat at rc 2, the local's `ownel` release returned
one, and the holder's plain drop walked elements only at rc→0 — where rc went 2→1, so it
returned nothing. `EmitLlvm::classDropFlavor()` now gives the drop the `own` flavor
whenever `$propOwnElem` — the module-wide store scan that already serves
release-before-overwrite — proves every store hands that slot element refs at the drop's
own depth. Wired into `dropRuntimeBody` and the cycle collector's `__cc_dropscalar_`.
`prop_from_local` and `prop_elem_hold` both go 60001/20001 → **60001/60001**, the whole
14-row table is flat, and the suite is 1026/1028, 0 failed — the epic's predicted 5 reds
do not appear, because the flavor is proven per SLOT rather than assumed for the buffer.
Full write-up: `docs/status/evidence/class-drop-ownel-2026-09-02.md`.

⚠⚠ **The ODR condition is the whole reason this is not a one-line change.**
`__mir_drop_<id>` is `linkonce_odr` and coalesces BY NAME across every object file that
emits the class, while `$propOwnElem` is MODULE-LOCAL — a program's verdict would
silently replace a library's conservative body for the same class, and the library's own
stores are invisible to it. So a LIBRARY module proves nothing, and an IMPORTED
(`isExternClass`) or PRELUDE class never takes the `own` flavor. Part splitting is safe:
`Main.php:626` splits the emitted IR TEXT, so a 45-part build still runs one scan.

**OPEN — flipping the default.** The gate has NOT seen a self-host gen-2, difftest, or
Linux. An over-release is invisible under Zend, invisible at -O0, and often invisible
until gen-2, so those are the price of default-ON — the same price the other two
ownership fixes paid. Until then no AOT case can test this (a suite case cannot set an
env var), so the regression test is owed with the flip, not before it.

## 6. Traps that cost time here

- **`retain_element` counts element STORES, not reads.** An element read emits no retain
  at all. I briefly reasoned the other way and nearly shipped a use-after-free.
- **The MIR dump prints the release FLAVOR (`mem_rc_release vec tmp`), not the element
  type.** Neither element fix is visible there — read the emitted `.ll` or the counters.
- **`MANTICORE_ALLOC_TRACE=1` on a compile instruments the TARGET binary.** To census the
  compiler itself it must be set for `bin/build`. Two layers of compile-time.
- **`ClassDef::$classId` is `stableClassId()`, a hash (~1e15).** An array indexed by it is
  not a table but a 7-petabyte allocation; the census keeps its own dense numbering.
- **Diagnostic code must be O(1) in the class count.** Unrolling a branch + `dprintf` per
  class made clang answer `cannot encode offset of relocations; object file too large`
  on a six-line program.
- **The local `php` has xdebug loaded**, which rewrites `var_dump` with a `file:line:`
  prefix. `difftest.sh` reported **335 DIFFs** against a tree whose suite was green
  minutes earlier. Fixed with `-d xdebug.mode=off`; results from before that are void.
- **`MANTICORE_STATS=1` breaks the T6 build**: `EmitLlvm: cannot hoist sink file`, with
  the exception text INTERLEAVED with the `fat fn: 2876187 bytes __mir_dump_object`
  stats line — two string buffers overlapping, i.e. a live string-lifetime bug, not
  merely "Stats is heavy". Reproduces deterministically. Root untouched.
- **`symfony-demo-probe/app` had 120 dead-generation `.dbg.ll*` files** and the volume was
  at 99% (6.8 GB free of 460). Deleting them restored 202 GB. Look there first on any
  disk-full.
- A test can mask its own fix: the first version of the destruct regression consumed the
  getter in RECEIVER position — itself a leak — so the object sat at rc 2, the overwrite
  dropped it to 1, and the working fix read as broken.
