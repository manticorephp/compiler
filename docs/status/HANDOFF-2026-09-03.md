## 1. The root, and it is not what the epic assumed

**The cycle-collector root buffer has no drain, so nearly nothing is ever freed.**

A decrement that leaves rc > 0 buffers the object as a possible cycle root
(purple + buffered). When its rc later reaches ZERO, `__mir_rc_release` decodes
the count correctly, reaches `free:`, and then refuses:

```llvm
; A *buffered* object is NOT freed here even at rc<=0 — the collector owns it
%bufb = and i64 %rc1, BUFFERED_MASK      ; = PHP_INT_MIN, the top bit
br i1 %isbuf, label %done, label %dofree
```

And the collector never runs. `__manticore_cc_collect_cycles` has exactly one
caller — the `gc_collect_cycles()` builtin — which nothing in the compiler
invokes. `cc_add_root` pushes onto a list that only ever GROWS.

So every object retained more than once leaks by construction. It fits every
measurement taken this session:

| observed | why |
|---|---|
| objects freed **0.27%** | only those that die on their FIRST decrement — never buffered |
| arrays reclaimed **96%** | arrays are not cycle candidates, so they are never buffered |
| `Lexer\Token` **0 of 168 705** | every token is retained more than once ⇒ every one is buffered |

⚠ **Until the collector works, no amount of retain/release correctness can free
a buffered object.** Several correct fixes this session moved nothing for exactly
this reason.

## 2. Where that leaves the collector — pick this up first

`MANTICORE_AUTO_GC=<threshold>` (default OFF) drains the buffer like php's 10 000
roots, with an `@__manticore_cc_active` re-entrancy guard.

**Fixed: the safe point.** Draining from `cc_add_root` runs a full mark/scan from
inside `__mir_rc_release` — the inliner flattens the two — on a mid-release
graph. Instant SIGSEGV, `cc_children+4` dereferencing a NULL class descriptor.
The trigger now lives in `__mir_alloc_tagged`, php's safe point for the same
reason: nothing is half-released and the new object is not yet reachable.

**Open: the collector's own double free.** Threshold 8 on a 3-line file:

```
stop reason = EXC_BREAKPOINT   libsystem_malloc mfm_free.cold
#1 mfm_free
#2 __mir_rc_release + 88
#3 __mir_array_release_ownel_obj
#4 __mir_drop_<id>
#5 __mir_rc_release
```

libmalloc's own abort — the block is freed twice. `collect_white` frees a white
object and ordinary rc then releases the same pointer; the surviving references
were never accounted for. Expected for code that has never run: its three phases
have never been exercised against a real object graph.

### Reproduce in seconds

```bash
env MANTICORE_PRELUDE="$PWD/prelude" MANTICORE_AUTO_GC=8 \
    bin/manticore build --apps-only <manifest-with-redirected-output>
env MANTICORE_PRELUDE="$PWD/prelude" lldb -b -o run -k "bt 10" -k quit -- \
    <that-binary> dump-ast /tmp/mc/tiny.php
```

`tiny.php` is three lines. Seconds per iteration, against the 22-minute tier runs
this epic started with.

### The order

1. Balance the trial-deletion phases: an object freed by `collect_white` must be
   removed from every surviving reference's accounting, and the buffered bit
   cleared exactly once. The malloc abort names the double free precisely.
2. Then threshold 10 000 and re-run the census — the prediction is that object
   reclaim leaves 0.27% for the first time.
3. Only then re-measure T6.

**Ownership fixes.**
- `array_merge` returned FREED objects — an erased element COPY emitted no
  retain at all. Fixed with the tag-dispatched `retainCellPayload`. A
  correctness bug, not a leak.
- The class drop gives back the element refs its slot owns (`vecobjown`).
- The `element-shared` veto is per callee; the by-ref veto is per method NAME.

- `returnRetainsBorrow` mirrors `isBorrowedObjReturn` for ARRAYS — the two

**Self-host:** gen-2 and gen-3 are BYTE-IDENTICAL (binary and stdlib), so the
fixpoint is reached at gen-2.

## 4. Instruments added — use these before theorising

- **`MANTICORE_ARR_RC_TRACE=1`** — per-BUFFER and per-OBJECT rc, with the
  resulting count. This is what found the root, in one run.
  ⚠ The printed rc is the RAW WORD: the live count is the LOW 56 BITS, the top
  byte is the collector's colour + buffered bit. `0x8100000000000000` is a live
  count of ZERO, buffered, purple.
- **Live class census** — `[CLASS] idx= alloc= free=`. It counted allocations
  only; the free half is new, and only alloc MINUS free answers "what is alive".
- **`MANTICORE_PHASE_TRACE=1`** — the phase timeline with `rss=<n>MB` per phase,
  WITHOUT the rest of `Stats` (which cannot be enabled on a large target).
- **Emission batch line** — `ir=`, `fattest=<KB> @<index> <name>`,
  `costliest=<MB> @<index> <name>` every 1024 functions.
- **`MANTICORE_DYNM_TRACE=1`** — why a dynamic-method site did not extract.
- `tools/prof/tier.sh` now caps on `max(rss, physical footprint)`.

## 5. Traps that cost time here

- ⚠⚠ **A module-wide veto on a per-name decision** is this codebase's recurring
  bug shape. Four instances this session: `$hasBag`, the site-wide by-ref veto,
  the `element-shared` veto, and the bare-name borrow key before them. Look for
  it FIRST in any emitter gate.
- ⚠⚠ **"Fattest by IR" and "costliest in memory" are different questions.** The
  batch trace reported the fattest, so a +5 GB batch was blamed on its fattest
  function and a "280x build multiplier" was inferred. A stand refuted it: a fat
  body costs 4–6x its own bytes and the ratio FALLS with size.
- ⚠⚠ **`tier.sh` capped on `ps rss`, which COLLAPSES under memory pressure**
  while the footprint climbs (2.9 GB vs 26.4 GB on one tick). The ceiling never
  applied and a run reached 40.8 GB on a 32 GB machine. Every capped peak is a
  measurement of the CAP, not of demand — compare RSS at equal batches instead.
- ⚠⚠ **`bin/build` runs pass 1 as `… 2>&1 | tee`**, so the APP pass's stderr is
  folded into bin/build's STDOUT. A `2>log` captures only pass 2 — the LIBRARY,
  which vetoes every slot by design — and the trace reads a confident ZERO.
- ⚠ **The sink-marker window in `EmitLlvm::emit`**: `$rawBodyPath = $meta[1]`
  is a BORROWED array element whose buffer `unset($meta, $body)` has freed. Any
  allocation between the read and its use rewrites the path. Putting a `substr`
  there killed the T6 build at function 46 088. Capture names OUTSIDE it.
- ⚠ **`sigs->refParams[$fn]` is a per-parameter BOOL ARRAY**, not a list of
  by-ref params — an ordinary 1-arg method is `[false]`, non-empty. Ask
  `anyRefParam()`; it owns the question.
- ⚠ **A co-ownership proof must be checked at BOTH ends.** The entry retain uses
  the PARAMETER's own flavor, so a param declared bare `array` retains in repr
  mode and co-owns nothing at element depth.
- ⚠ **`$module->functions` is DRAINED during emission** — resolving a name from
  an index later prints `?`.
- ⚠ **A binary run from outside the checkout needs `MANTICORE_PRELUDE=<root>/prelude`**
  or it dies in under a second with `prelude: cannot read var_export.php`, which
  reads exactly like a fast successful build.
- ⚠ **Disk**: one orphaned `/private/tmp/manticore_<pid>-<hash>.o.tmp` held
  **131 GB**. `*.dbg.ll*` was already clean, so a name-based search finds
  nothing. Run `du -sh /private/tmp/* | sort -rh | head` first.

## 6. Two things this session DISPROVED

- **"Annotate the 237 bare arrays and the erased channel closes."** Not
  established. Wiring the promoted-parameter `@var` (the AST classes annotate
  the PARAMETER, and `Param` had no `docComment` field at all) end to end gave
  **283 element-owning class drops before, 283 after — zero new**:
  `LowerClasses` already recovers those element types by usage inference.
  Reverted. Attack the 237 only where a measurement shows real erasure.
  ⚠ Note the honest number is 237 (`analyze src --only array.no-value-type`),
  not the 963 bare `array` hints — most already carry docblocks the compiler
  reads. Docblock generics are ALREADY implemented (`LowerTypes::docTagType`
  for `@var` / `@param` / `@return` / locals; native `array<K,V>` and `T[]` too).
- **A "~280x per-function build multiplier".** Refuted by a stand, as above.

## 7. Method note

Three attempts to explain the token leak by reading emitter predicates produced
**two no-ops and one masked fix**. The rc trace answered it in a single run.
Both reverted changes were written before a failing test existed.

**Build the observation before arguing about the mechanism, and get the red
first** — otherwise "it should help" and "it helps" are indistinguishable.
