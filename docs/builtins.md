# Builtin coverage — what Manticore ships of PHP, and what it adds

_Generated by `php tools/builtins_audit.php` against PHP 8.5.10 on 2026-09-23. Do not edit by hand._

Every internal function and class the reference `php` declares (its bundled
extensions; xdebug, openswoole, Zend OPcache, mysqlnd excluded) is checked against
what Manticore defines in its three tiers:

| Tier | Where | What it means |
|---|---|---|
| `b` | `src/Compile/Mir/Passes/EmitLlvmBuiltins.php` | a codegen builtin — emitted inline as LLVM IR / a libc call |
| `l` | `src/Compile/Mir/Passes/Lower*.php`, the parser | lowered: resolved at compile time with no runtime body (`define`, `func_get_args`, `compact`, …) |
| `s` | `src/Runtime/Stdlib/*.php` → `lib/manticore_stdlib.o` | written in PHP, compiled once, auto-linked when called |
| `p` | `prelude/*.php`, `src/Runtime/*.php` | PHP injected into every program that mentions it |
| `i` | `src/Analyze/Builtins.php` | an intrinsic class the engine provides with no PHP body (`Closure`, `Generator`, `Fiber`, …) |

**Presence is not parity.** A name in the implemented column means the call
compiles and runs; behaviour is graded by `tools/difftest.sh` against `php`.
A name in the missing column compiles (the call resolves to nothing) and traps
at run time with `Call to undefined function`.
